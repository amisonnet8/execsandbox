# CLI出力

## ホスト側ログとゲストstderrの区別

ExecSandboxには**2種類のstderr**が存在する（仕様書§7.7）。これを混同しない
ことが、この文書で最も重要な点である。

| 出力元 | 内容 | 制御 |
| :--- | :--- | :--- |
| ホスト（ExecSandbox本体） | 起動エラー、tail-dropの記録、フレーム長超過の記録 | `-q, --quiet` で抑制 |
| ゲスト（WASMモジュール） | モジュール自身の出力、ランタイムのpanicメッセージ | `-s err` で有効化（既定は遮断） |

**ホスト側の出力には `execsandbox:` を接頭辞として付ける。** 両者が同じ端末に
流れたとき、どちらが出したものか判別できなくなるため。

既定値が逆である点にも注意すること。ホスト側ログは既定で出力し、ゲストのstderrは
既定で遮断する。ゲスト側は明示的に配線しない限り何もできない、というケイパビリティ
の原則に従う一方、ホスト側は運用者が見るべき情報だからである。

## ログのレート制限

tail-drop（仕様書§3.6）は、受信側が詰まっている間**継続的に発生し続ける**。
1通ごとに1行出すと秒間数千行になりかねない。

- 初回のみ出力し、以降は一定間隔で累計破棄数を出力する。
- 同種の「継続的に発生しうるイベント」を新しくログに出す場合も、同じ扱いを
  検討すること。

## 何をログに出し、何を出さないか

判断基準は「静的か動的か」である（仕様書§3.4）。

- **出さない**：未設定の宛先への送信。起動オプションを見れば分かる静的な状態
  であり、Unixの `/dev/null` と同じく通知を要しない。
- **出す**：tail-drop、フレーム長超過。実行中の状況に依存する動的な現象であり、
  記録しなければ外から観測できない。

新しい「黙って捨てる」挙動を実装するときは、この基準でどちらか判断すること。

## ゲストには通知しない

ホストが記録する事象を、**ゲストへ通知してはならない**。tail-dropもフレーム長
超過も、ゲストが知る手段を持たないことが仕様である（仕様書§3.4、§3.6）。
デバッグのしやすさを理由にABIへ通知経路を足したくなっても、それは
Push型モデルを壊す変更である（`.claude/rules/abi-compatibility.md`）。

## 装飾ライブラリは導入しない

色付け・罫線・プログレスバー・TUI等のライブラリは入れない。

- ExecSandboxの出力は「起動時のエラー」と「運用ログ」がほぼすべてであり、
  装飾する対象がない。
- 本体のサイズ増加はビルダーで6倍に増幅される
  （`.claude/rules/binary-size.md`）。
- ログはリダイレクトされてファイルに残ることが前提であり、ANSIエスケープは
  むしろ邪魔になる。

## 出力の言語は英語

**CLIの出力（標準出力・標準エラー出力）はすべて英語で書く。** ドキュメント・
コメント・コミットメッセージは日本語という方針（`CLAUDE.md`）の例外である。

理由は、CLIの出力がドキュメントとは性質の異なるものだからである。

- **機械的に扱われる。** `grep`・パイプ・ログ収集基盤を通る。日本語だと環境に
  よっては文字化けし、フィルタも書きにくい。
- **第三者が読む。** issueやStack Overflowに貼られたとき、日本語だと検索にも
  引っかからず、報告者以外に伝わらない。
- **利用者が日本語話者とは限らない。** ドキュメントは読者を選べるが、エラーは
  誰の環境でも出る。

対象は以下すべて。

- ホスト側ログ（`execsandbox:` で始まる行）
- 起動時のエラーメッセージ
- `--help` / `--version` の出力

テストがこれらの文言を検証する場合も、当然英語で書く。

## エラーメッセージ

- **起動を中止するエラーは、何が足りないかを具体的に示すこと。** 特に
  「WASMモジュールが埋め込まれていない」（仕様書§6.2）は、素のベースバイナリを
  直接実行した場合に出るため、ビルダーの使い方を案内する。
- 設定ミスに由来するエラー（`-d` の書式不正、`-l` のアドレス不正など）は、
  正しい書式を併記する。

## 標準出力は使わない

ホスト側の出力はすべてstderrへ書く。標準出力はゲストのものである（`-s out`）。
ホストがstdoutに何か書くと、ゲストの出力に混ざって利用者のパイプ処理を壊す。
`--version`・`--help` のみ例外としてstdoutでよい。
