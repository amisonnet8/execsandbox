# 命名規則

ExecSandboxでは、**ABI関数名・SDK関数名・CLIオプション名**を、できる限り対応
させる方針を採る。ExecDBが `Save()`/`SaveSelf()` という命名をコマンド名
（`.snapshot`/`.overwrite`）とずらしてしまい、後から
`Snapshot()`/`Overwrite()` へ統一し直した経緯がある。同じ轍を踏まないこと。

## 対応表（現在の一覧）

| ABI関数（仕様書§5） | SDK関数（TinyGo、参考） | CLIオプション |
| :--- | :--- | :--- |
| `send(dest, ptr, len)` | `Send(dest int, data []byte)` | ─（宛先の割り当ては `-d`） |
| `recv(meta, buf, cap, timeout)` | `Recv()` / `RecvTimeout(d)` | ─ |
| `conn_write(conn_id, ptr, len)` | `ConnWrite(connID uint32, data []byte)` | ─（待ち受けは `-l`） |
| `max_frame()` | `MaxFrame() int` | `-f` / `--max-frame` |

`send`/`recv`/`conn_write` にCLIオプションの対応がないのは意図通り。これらは
実行時にゲストが呼ぶ操作であり、起動時の設定ではないため。代わりに「そもそも
送れる先があるか」「待ち受けるか」を決めるオプション（`-d`/`-l`）が対応する
位置にある。

`max_frame()` だけがCLIオプションと直接対応する。ホストの設定値をゲストが
読み取るための関数であるため。

## ABI関数名は `snake_case`

WASMのインポート名は `snake_case` とする（`conn_write`、`max_frame`）。
Goの命名規則（`connWrite`）ではなく、WASM/WASIの慣習に合わせる。

**SDK側は各言語の慣習に従ってよい**（Goなら `ConnWrite`、Rustなら
`conn_write`）。ABI名とSDK名が字面として一致しないのは問題ない。対応関係が
明確であればよい。

## CLIオプション

- 短縮フラグは1文字。**長い形式（`--name`）と短縮形式（`-n`）は必ずセットで
  用意する**（仕様書§7.1）。
- `-h` は `--help` の定位置として予約済み。他のオプションで使わないこと。
- **短縮フラグは小文字を原則とする。例外は `-V`（`--version`）と
  `-L`（`--print-licenses`）の2つ。**
  - `-V` は `-v` をマウント（volume、Dockerと同じ割り当て）に使っている以上、
    大文字に逃がすほかない**必然的な**例外。
  - `-L` は未使用の小文字（`-p` 等）も選べたが、`-V` と対にして大文字にした
    ——**任意の**例外。理由は、両者とも「サンドボックスの実行そのものには
    関与しない、情報表示だけの機能」という共通点を持ち、`-h`/`-V` と並べた
    ときに `-L` だけ小文字で浮くよりも、情報表示系3つのうち `-V`/`-L` を
    大文字で揃えたほうが一覧性が高いと判断したため（仕様書§7.1）。
  - 新しいオプションを追加する際は、まず未使用の小文字を探すこと。大文字へ
    逃がすのは、`-V` のように既に小文字が塞がっている場合、または `-L` の
    ように既存の大文字オプションと明確に対になる場合に限る。
- `-v` は**マウント**であり、verboseではない。
- 列挙を取るオプション（`-s`、`-x`）はカンマ区切り。

## 新規追加時

新しいホスト関数を追加する場合、以下を同時に確認・更新すること。

1. ABI関数名（`snake_case`）
2. 対応するCLIオプションがあるか
3. 仕様書§5の表
4. この対応表
5. `docs/spec/sdk_binding_ja.md`（SDKからどう見えるか。暫定文書）

SDKライブラリの実装そのものは別リポジトリ（`execsandbox-sdk`）にあるため、本
リポジトリでは更新しない。**ただしABIを追加したら、SDK側が追随できるよう仕様書を
先に確定させること**（`.claude/rules/abi-compatibility.md`）。

ABIの追加は互換性に直結するため、`.claude/rules/abi-compatibility.md` も
必ず確認すること。

## 用語の統一

仕様書§1で定義した用語を、コード・コメント・ログでも一貫して使うこと。
特に以下は混同しやすい。

| 使う語 | 使わない語 |
| :--- | :--- |
| メールボックス | キュー、チャネル、バッファ |
| 宛先 | 送信先、ターゲット |
| ホスト / ゲスト | サーバー / クライアント |
| 外部接続 | TCP（Unixドメインソケットの場合もあるため） |

「チャネル」は設計初期に捨てた概念であり（仕様書§1の用語表）、この語が
コード内に現れたら設計の理解がずれている兆候と考えてよい。
